System Overview & Core Objectives

FISCAL is an enterprise custom tax management workspace engineered for administrative precision, regulatory compliance, and mathematical transparency. In contrast to manual spreadsheets or opaque accounting software, FISCAL couples a normalized relational database schema with authoritative server-side computation engines, atomic database transaction controls, and a bespoke tactile user interface.

Relational Design
5 Normalized Tables
3NF Architecture with Foreign Key Cascades
Transaction Guarantee

Arithmetic Precision

Zero floating-point rounding divergence
Cloud Hosting
Render + Supabase
Docker container + Managed PostgreSQL pooler
SECTION 1 • FULL-STACK ARCHITECTURAL TOPOLOGY

Four-Tier Enterprise System Architecture

FISCAL adheres to a clean separation of concerns across presentation, routing, business services, and database persistence layers:

TIER 1 • PRESENTATION

Client UI & Visualization

Responsive single-page architecture built with semantic HTML5, zero heavyweight JS frameworks, bespoke Matcha & Milk Honey design tokens, and a Three.js WebGL canvas displaying real-time 3D database cluster visualizations.

HTML5 Vanilla CSS3 ES6 JavaScript Three.js 3D
TIER 2 • CONTROLLERS

HTTP & Servlet Dispatcher

Lightweight embedded server (FiscalDevServer) / Jakarta Servlet endpoints handling incoming HTTP methods (GET, POST, PUT, DELETE), JSON payload deserialization (Gson), session token extraction, and response formatting.

Java 17 Jakarta Servlets Google Gson REST APIs
TIER 3 • BUSINESS LOGIC

Statutory Calculation & Rules

Domain layer enforcing business validation (PAN regex, age bounds), the statutory calculation engine (Applicable Amount × Rate / 100), PBKDF2 password hashing, and payment state machine transitions (PAID, PENDING, REVERSED).

TaxCalculationEngine AuthService PBKDF2 Hashing State Machine
TIER 4 • PERSISTENCE

Database & Connection Pool

Authoritative relational storage hosted on Supabase Cloud PostgreSQL (backed by Oracle 23ai DDL/DML compatibility), accessed via JDBC PreparedStatement parameterized queries with connection pooling and atomic commit/rollback.

Supabase Cloud PostgreSQL 15+ JDBC Driver Connection Pooler
SECTION 2 • RELATIONAL SCHEMA & DATA DICTIONARY

Entity-Relationship Architecture & Table Specifications

The database schema is designed in Third Normal Form (3NF), enforcing mathematical constraints, foreign keys with referential integrity, and unique indexes:

1. TAXPAYER Master Registry
🔑 TAXPAYER_ID BIGINT PRIMARY KEY
NAME VARCHAR(100) NOT NULL
PAN_NO VARCHAR(10) UNIQUE CHECK
AGE INT CHECK (18 <= AGE <= 120)
CITY VARCHAR(100) NOT NULL
INCOME NUMERIC(14,2) CHECK (>= 0)
CREATED_AT TIMESTAMPTZ DEFAULT NOW()
2. TAX_TYPE Statutory Categories
🔑 TAX_TYPE_ID BIGINT PRIMARY KEY
TAX_NAME VARCHAR(100) UNIQUE NOT NULL
TAX_RATE NUMERIC(5,2) (0% to 100%)
DESCRIPTION VARCHAR(255)
CREATED_AT TIMESTAMPTZ DEFAULT NOW()
3. TAX_RECORD Assessment Ledger
🔑 TAX_ID BIGINT PRIMARY KEY
🔗 TAXPAYER_ID FK -> TAXPAYER (CASCADE)
🔗 TAX_TYPE_ID FK -> TAX_TYPE (CASCADE)
TAX_AMOUNT NUMERIC(14,2) CHECK (>= 0)
STATUS PAID | PENDING | REVERSED
CREATED_AT TIMESTAMPTZ DEFAULT NOW()
4. TAX_PAYMENT Financial Settlements
🔑 PAYMENT_ID BIGINT PRIMARY KEY
🔗 TAX_ID FK -> TAX_RECORD (CASCADE)
AMOUNT_PAID NUMERIC(14,2) NOT NULL
PAYMENT_DATE TIMESTAMPTZ DEFAULT NOW()
PAYMENT_MODE NET_BANKING | UPI | RTGS
PAYMENT_STATUS PAID | PENDING | REVERSED
PAYMENT_REF VARCHAR(50) UNIQUE AUDIT
5. APP_USER Authentication & RBAC
🔑 USER_ID BIGINT PRIMARY KEY
USERNAME VARCHAR(50) UNIQUE NOT NULL
PASSWORD_HASH VARCHAR(255) PBKDF2 HASH
SALT VARCHAR(64) CRYPTO SALT
ROLE ADMIN | OFFICER | AUDITOR
ACTIVE / STATUS ACTIVE | INACTIVE
SECTION 3.1 • COMPUTATIONAL SPECIFICATION

Statutory Calculation Engine

Calculations are executed server-side via the statutory equation:

Tax Amount = Applicable Amount × Tax Rate ÷ 100
  • Rounding Mode: RoundingMode.HALF_UP applied at exactly 2 decimal decimal places.
  • Type Safety: Strict Java BigDecimal arithmetic prevents floating-point precision loss.
  • One-Click Ledger Transition: Workbench results can be committed directly to official ledger records.
SECTION 3.2 • CRYPTOGRAPHY & ACCESS CONTROL

FIPS Cryptographic Security

Password verification and session safety follow institutional security standards:

PBKDF2WithHmacSHA256 • 10,000 Iterations • 16-Byte Salts
  • Constant-Time Comparison: MessageDigest.isEqual prevents timing analysis attacks.
  • Session Fixation Protection: Active sessions are rotated upon every successful authentication.
  • Role-Based Authorization (RBAC): Granular permissions partitioned between Admin, Assessment Officer, and Auditor.

About FISCAL — Custom Tax Management

ORACLE 23ai / 19c ENTERPRISE JAVA 17 SERVLETS + JDBC MATCHA & MILK HONEY PALETTE PBKDF2 SECURITY

Clarity in every calculation.

FISCAL is an authoritative custom tax management system engineered to eliminate spreadsheet errors, opaque tax assessments, and untracked ledger modifications. The application establishes a single source of truth backed by Oracle Database, authoritative server-side calculation routines, and a warm, editorial interface.

Demographic Registry

Regex-validated PAN format, strict age bounds (18–120), and masked display for taxpayer privacy.

Statutory Tax Rules

Configurable statutory categories (Income Tax, GST, Capital Gains, Corporate Tax) with rate bounds.

Calculation Workbench

Authoritative server-side formula Tax = Amount × Rate / 100 with HALF_UP rounding precision.

Audit & Ledger Engine

Atomic transaction states (PAID, PENDING, REVERSED) with rollback and audit trail logging.
