# FISCAL — Oracle Database Schema Specification

## 1. Overview
FISCAL utilizes an enterprise-grade Oracle Database relational schema designed specifically for the Custom Tax Management PAT project. The database architecture enforces mathematical precision, referential integrity, check constraints on statutory rules, and audit readiness.

## 3. Data Dictionary

### 3.1 Table: `TAXPAYER`
Stores personal identification, statutory PAN numbers, demographic age, and annual declared gross financial income.

| Column Name | Data Type | Nullable | Constraint | Description |
|---|---|---|---|---|
| `TAXPAYER_ID` | `NUMBER` | No | `PK_TAXPAYER` | Primary identifier (Auto-generated by `TAXPAYER_SEQ`) |
| `NAME` | `VARCHAR2(100)` | No | — | Full legal name of the taxpayer |
| `PAN_NO` | `VARCHAR2(10)` | No | `UQ_TAXPAYER_PAN`, `CHK_TAXPAYER_PAN_LEN` | 10-character statutory Permanent Account Number |
| `AGE` | `NUMBER(3)` | No | `CHK_TAXPAYER_AGE` | Age in years (`18 <= AGE <= 120`) |
| `CITY` | `VARCHAR2(100)` | No | — | City of tax jurisdiction |
| `INCOME` | `NUMBER(14, 2)` | No | `CHK_TAXPAYER_INCOME` | Declared annual gross taxable base (`INCOME >= 0`) |
| `CREATED_AT` | `DATE` | No | Default `SYSDATE` | System entry timestamp |

### 3.2 Table: `TAX_TYPE`
Defines statutory tax categories and configured percentage assessment rates.

| Column Name | Data Type | Nullable | Constraint | Description |
|---|---|---|---|---|
| `TAX_ID` | `NUMBER` | No | `PK_TAX_TYPE` | Primary identifier (Auto-generated by `TAX_TYPE_SEQ`) |
| `TAX_NAME` | `VARCHAR2(100)` | No | `UQ_TAX_TYPE_NAME` | Category name (e.g. Income Tax, GST, Corporate Tax) |
| `TAX_RATE` | `NUMBER(5, 2)` | No | `CHK_TAX_TYPE_RATE` | Statutory percentage rate (`0.00 <= TAX_RATE <= 100.00`) |
| `DESCRIPTION` | `VARCHAR2(255)` | Yes | — | Statutory rule details and applicability guidelines |
| `CREATED_AT` | `DATE` | No | Default `SYSDATE` | Creation timestamp |

### 3.3 Table: `TAX_PAYMENT`
Authoritative transactional ledger recording tax payments, assessments, remittance dates, and reconciliation statuses.

| Column Name | Data Type | Nullable | Constraint | Description |
|---|---|---|---|---|
| `PAYMENT_ID` | `NUMBER` | No | `PK_TAX_PAYMENT` | Primary identifier (Auto-generated by `TAX_PAYMENT_SEQ`) |
| `TAXPAYER_ID` | `NUMBER` | No | `FK_PAYMENT_TAXPAYER` | References `TAXPAYER(TAXPAYER_ID)` (`ON DELETE CASCADE`) |
| `TAX_ID` | `NUMBER` | No | `FK_PAYMENT_TAX_TYPE` | References `TAX_TYPE(TAX_ID)` |
| `AMOUNT` | `NUMBER(14, 2)` | No | `CHK_PAYMENT_AMOUNT` | Monetary remittance in INR (`AMOUNT >= 0`) |
| `PAYMENT_DATE` | `DATE` | No | Default `SYSDATE` | Settlement timestamp |
| `STATUS` | `VARCHAR2(20)` | No | `CHK_PAYMENT_STATUS` | Transaction status: `'PAID'`, `'PENDING'`, `'REVERSED'` |
| `PAYMENT_REF` | `VARCHAR2(50)` | No | `UQ_TAX_PAYMENT_REF` | Unique audit reference (e.g. `FSC-2026-5001`) |
| `REMARKS` | `VARCHAR2(255)` | Yes | — | Audit trail note or banking batch reconciliation remarks |

### 3.4 Table: `APP_USER`
System operators and credentials using PBKDF2 cryptographic hashing and salts.

| Column Name | Data Type | Nullable | Constraint | Description |
|---|---|---|---|---|
| `USER_ID` | `NUMBER` | No | `PK_APP_USER` | Primary identifier (Auto-generated by `APP_USER_SEQ`) |
| `USERNAME` | `VARCHAR2(50)` | No | `UQ_APP_USER_USERNAME` | Unique login username |
| `PASSWORD_HASH` | `VARCHAR2(255)` | No | — | Hexadecimal PBKDF2WithHmacSHA256 (32 bytes) |
| `SALT` | `VARCHAR2(64)` | No | — | 16-byte cryptographically secure random salt |
| `FULL_NAME` | `VARCHAR2(100)` | No | — | Operator display name |
| `EMAIL` | `VARCHAR2(100)` | No | `UQ_APP_USER_EMAIL` | Contact email address |
| `ROLE` | `VARCHAR2(20)` | No | `CHK_APP_USER_ROLE` | Access role: `'ADMIN'`, `'OFFICER'`, `'AUDITOR'` |
| `STATUS` | `VARCHAR2(20)` | No | `CHK_APP_USER_STATUS` | Account state: `'ACTIVE'`, `'INACTIVE'` |
| `CREATED_AT` | `DATE` | No | Default `SYSDATE` | Account provisioning date |

## 4. Performance Indexes
- `IDX_TAXPAYER_NAME` on `TAXPAYER(NAME)`
- `IDX_TAXPAYER_CITY` on `TAXPAYER(CITY)`
- `IDX_PAYMENT_TAXPAYER` on `TAX_PAYMENT(TAXPAYER_ID)`
- `IDX_PAYMENT_TAX_TYPE` on `TAX_PAYMENT(TAX_ID)`
- `IDX_PAYMENT_DATE` on `TAX_PAYMENT(PAYMENT_DATE)`
- `IDX_PAYMENT_STATUS` on `TAX_PAYMENT(STATUS)`
